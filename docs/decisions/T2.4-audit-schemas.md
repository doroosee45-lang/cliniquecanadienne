# T2.4 — Audit des schémas Mongoose (index, références, champs requis)

**Portée :** 36 modèles présents dans `backend/models/` (35 + `Counter.js`, ajouté en cours de projet).
**Méthode :** extraction systématique de tous les appels `.index()`, `unique: true` et `ref:` sur les 36 fichiers, puis vérification manuelle de la cohérence de chaque référence et de chaque champ `required` par rapport à la règle métier réelle qu'il modélise.
**Portée volontairement exclue :** l'ajout des index manqués n'a pas été fait dans cette tâche — T2.4 est un audit (« Vérifier… Consolider »), pas une tâche de correction. Voir la colonne Remarque pour ce qui est recommandé en suivi.

## Légende
- **OK** : index/refs/required cohérents avec l'usage réel du modèle.
- **À corriger** : lacune identifiée (essentiellement des index manquants sur des champs de filtre fréquent — aucune référence erronée ni `required` incohérent trouvé sur l'ensemble des 36 modèles).

## Test de vérification — `getIndexes()` réel, base de développement

Exécuté contre la base réelle pour confirmer que les index déclarés dans les schémas sont bien construits en base (pas seulement présents dans le code) :

```
patients        : _id_, numero_dossier_1 (unique), index texte (nom/prenom/numero_dossier/telephone)
appointments    : _id_, date_heure_1_medecin_1, patient_1
invoices        : _id_, numero_facture_1 (unique), patient_1_date_facture_-1, statut_1
auditlogs       : _id_, utilisateur_1_createdAt_-1, module_1_action_1
hospitalizations: _id_  ← confirme l'absence totale d'index secondaire constatée dans le tableau
consultations   : _id_  ← idem
```

Concordance exacte entre le tableau de synthèse (issu de la lecture du code) et l'état réel de la base — aucun écart entre schéma déclaré et index effectivement construit.

## Recommandation de suivi (non exécutée dans cette tâche)

Ajouter les index listés « à corriger » est une opération sûre et non destructive (Mongoose/MongoDB construisent un index en arrière-plan sans verrouiller la collection sur les versions récentes) — candidate naturelle pour un lot de correction rapide et à faible risque, séparé de cette tâche d'audit. Priorité suggérée si ce lot est validé : Hospitalization, Consultation, Urgence, Prescription, ImagingResult, Patient.email.
