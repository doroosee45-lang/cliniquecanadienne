# T4.2 (R-01a) — Clarification : rôle infirmier sur les routes d'écriture Chirurgie

**Statut :** Clarifié — pas une correction, `chirurgieRoutes.js` inchangé.

## Contexte

La description originale de T4.2 (R-01a) demandait `authorize('superadmin','adminclinique','medecin','infirmier')` sur les routes d'écriture de `chirurgieRoutes.js`. Vérification du code actuel (Phase 9, audit T9.5) : le fix protège bien **toutes** les routes (aucune n'est ouverte sans `authorize()`, ce qui était l'enjeu sécurité initial de R-01a), mais avec une répartition différente :

```js
const CHIR_ROLES  = ['superadmin', 'adminclinique', 'medecin', 'infirmier'];  // lecture + bilan
const CHIR_MANAGE = ['superadmin', 'adminclinique', 'medecin'];               // création/modification/complications
```

`infirmier` a accès en lecture complète et peut ajouter un bilan (`POST /:id/bilan`), mais pas créer/modifier le dossier principal ni déclarer une complication — contrairement à la description initiale de T4.2 qui l'incluait dans l'écriture complète.

## Décision

Ce n'est **pas un écart à corriger**. `docs/decisions/baseline-checklist-10x23.md` (note 4) documente déjà cette répartition exacte comme une décision Phase 2 délibérée et vérifiée par test : *« Infirmier sur Chirurgie — lecture complète + ajout de bilan (/bilan), mais pas de création/modification du dossier principal ni des complications. Conforme à "bloc opératoire : lecture/participation", déjà vérifié explicitement par test en Phase 2. »*

La description originale de T4.2 est donc **supersédée** par cette décision Phase 2, postérieure et plus précise. Aucun changement de code — `chirurgieRoutes.js` reste tel quel.

## Conséquence pour l'audit T9.5

Ne pas traiter ce point comme un trou de couverture ou un correctif manquant : le comportement actuel est le comportement voulu, déjà testé.
